# How PlayTorrioMov works

The diagram is [INFO.excalidraw](INFO.excalidraw). This is the same thing in
prose, for reading rather than looking at, and it is where the *why* lives —
the diagram has room for what a box is, not for why it is shaped that way.

The diagram is generated by `scripts/gen_info_diagram.ps1` and checked by
`scripts/check_info_diagram.ps1`. Edit the script, not the file: it is 91
elements of near-identical JSON, and hand-editing is how the previous version
ended up with a stray line and no arrows.

---

## The shape of it

Eight bands, top to bottom. Arrows only ever point down, so the reading order
is the flow and nothing has to be followed backwards.

```
STARTUP      main.dart -> HubPage
SECTIONS     Movies · Series · Anime · Live TV · Library
SOURCES      addons · built-in scrapers · Live TV · anime
BROWSING     WatchScreen
PLAYBACK     PlayerScreen
MENUS        audio/subtitles · speed/aspect · sources/episodes · sleep/cast
SERVICES     P2P · subtitles · metadata · debrid/downloads
PERSISTENCE  SharedPreferences + sqflite
```

The colors are the only thing in the diagram that is not self-explanatory,
so it carries a legend: blue is entry and shell, green is where content comes
from, orange is browsing and playback, purple is a service playback pulls in,
yellow is persistence.

## Startup

`main.dart` does four things before any widget exists, and the order matters.

1. **`WidgetsFlutterBinding.ensureInitialized()`**, then a Linux-only pin of
   `path_provider` and `shared_preferences` to the app's original
   `com.mediahub.playtorriomov` id. The Flatpak sets the GApplication
   `application-id` to the Flatpak's own id so the compositor can associate
   the window with the installed `.desktop` file — but `path_provider_linux`
   reads its data directory from that same property, so the taskbar fix
   silently forked every existing install's library into a new, empty
   directory. The pin is what stops that happening again.
2. **`MediaKit.ensureInitialized()`** — libmpv has to be up before anything
   can ask it about a file.
3. **`window_manager`**, on desktop only.
4. **~20 services, in parallel** via `Future.wait`. Two of them are awaited
   rather than fired and forgotten, because something reads them
   synchronously on the first frame: `SourceFilterSettings` (the watch screen
   seeds its dropdowns from it) and `BuiltinProvidersService` (the first
   `scrapeAll` reads which scrapers are switched off).

`HubPage` is then the whole app: `AdaptiveNavShell` for the chrome, one
`NestedNavigator` for the content, and a `MediaHub` inside it. The nested
navigator is what lets a Details page be pushed *inside* a section, so
switching section from the pills or the bottom bar pops back to that
section's root instead of leaving the Details page on top of the switch.

## Where content comes from

Four sources, and they are not interchangeable.

**Addons** are Stremio-compatible: a catalog add-on supplies the rows, a
stream add-on supplies the sources. The same catalog and meta responses
supply titles, artwork, and baseline descriptions, defaulting to Cinemeta
when a configured base URL is missing. This is the only source that is
user-extensible without a code change.

**Built-in scrapers** are ~50 site-specific parsers behind `ScraperManager`,
which fans a title out to all of them and merges the results into
`StreamService`. Each has its own deadline; a slow one is dropped rather than
allowed to hold the list.

**Live TV** is Xtream portals and M3U playlists, with its own controller,
favorites and custom channels. It is the area this fork has diverged
furthest in.

**Anime** is AniList for metadata and its own scraper path, plus a separate
Arabic catalog.

**One hub, five sections, Library always last.** Phones show them in the
bottom tab bar; tablet and desktop show them as a chip row under the top bar.
Search stays an icon rather than becoming a sixth section, because it is a way
into the other five rather than a place of its own.

## Browsing

`WatchScreen` is the source list. It is where the filter pills live — audio
language, quality, size — and where the multi-select filters apply. The
filters are a *standing preference* (they persist and apply to every title);
the size range and sort order are per-episode browsing choices and stay on
this screen rather than moving into Settings.

The pill rail is shared by the phone and desktop layouts, so its edge
affordances are split by **platform**, not width: the fade is drawn
everywhere, the scroll button only on desktop. A tablet is wide enough to
pass any breakpoint and is still a touch device, where the row is dragged and
a button over the first and last pill would swallow taps meant for them.

---

## Playback

`PlayerScreen` is media_kit over libmpv. The transport, seek bar and keyboard
shortcuts are all here, and so is the decision that shapes the rest of the
player: **media_kit's own subtitle view is off**, and a Flutter
`SubtitleOverlay` draws the text instead. That is what makes alignment and
vertical position actually apply — mpv's own view ignores them.

The cost of that decision is the embedded-subtitle problem. An embedded
ASS/SSA track is rendered *by libass* and never emitted as text, so the
overlay has nothing to draw. An embedded track therefore has to turn libass
back on, which is what `_enableLibassForEmbedded()` does — and it passes
`forceLibass: true`, because `applySubtitleStyling` otherwise honours the
`useLibass` preference (off by default) and sets `sub-visibility=no`,
undoing the fix two lines above it.

## The player's menus

Four, each with its own icon, all the same width (`PlayerTheme.menuWidth`),
all using the same row shape (`PlayerMenuRow`) and the same selection mark.

| Menu | What it holds |
|:--|:--|
| Audio & Subtitles | track pickers, subtitle sync, the style editor |
| Speed & Aspect | playback rate, crop and scale |
| Sources & Episodes | switch source, next episode |
| Sleep timer & Cast | 10/15/30/45/60 min, end of video, DLNA |

They were briefly merged into one panel and unmerged on request. The
consistency work that came out of it stayed: one width, one row shape, one
radio mark, so they can be grouped under a single settings icon later without
redesigning any of them.

## Services playback pulls in

**P2P** — TorrServer plus libtorrent. A magnet becomes an HTTP stream on
`127.0.0.1`, which is why casting a torrent from a phone is an open question:
a receiver asked to fetch `127.0.0.1` asks itself.

**Subtitles** — embedded tracks through libass, plus online providers that
return a couple of hundred languages for a popular title. The list is sorted
by how many files each language has and capped, because most of those
languages have exactly one file.

**Metadata** — Stremio/Cinemeta supplies catalog rows and baseline
descriptions; TMDB supplies the details-page synopsis in the viewer's
language plus cast enrichment when a key exists, falling back silently
otherwise. Addons usually send `imdb_id`, so the page resolves it to a TMDB
id and caches the result. Simkl and Trakt sync, AniList covers anime.
AniList returns four titles per show and the app picks one.

**Debrid & Downloads** — Real-Debrid and friends for cached sources, and
offline files.

## Persistence

`SharedPreferences` for settings, `sqflite` for the library, history and
progress. Everything above feeds it, which is why the arrows into it are
dashed: it is not a step in the flow, it is what every step leaves behind.

---

## Two things worth knowing before changing anything

**A title is two fields, and they must never merge.** `displayTitle` is what
the user reads and is localizable; `canonicalTitle` is what scrapers query,
what `uniqueKey` hashes, and what Trakt and Simkl match on, and must never be
translated. All 48 scrapers search by title string against release names,
which are English or original-language — a translated title returns nothing,
and it fails silently. The full reasoning is in
[CONVENTIONS.md](CONVENTIONS.md#titles).

**Dependencies point inward.** `pages → widgets → services → models`. A model
depends on nothing. This is what keeps the scrapers, the player and the
catalog independently testable, and it is the rule most worth not breaking
for a quick fix.
